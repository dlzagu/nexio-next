# ADR-0006: 쓰기 경로 — 좁은 관문 · 상태 전이 정본 · 이력 규약

- 날짜: 2026-08-14
- 상태: 채택 (ADR-0004 가 남긴 "쓰기는 자체 DB 로 가능해졌다"를 실제 구현으로 확정)

## 맥락

읽기 경로는 3화면 모두 끝났지만 쓰기는 `ALLOW_DEV_WRITES=false` 로 막힌 채 202/501 만
돌려주고 있었다. 남은 선택은 "어떻게 쓸 것인가" 하나였다. 원본 시스템은 이 규칙이
JSP 전역(버튼 25종 × 상태 12 × 권한축 11)에 흩어져 있었고, 그게 6,611줄의 직접 원인이었다.
같은 실수를 반복하지 않는 것이 이 결정의 목적이다.

## 결정

### 1. 읽기와 쓰기는 **다른 문**으로 들어간다

`select()` 는 그대로 SELECT/WITH 전용으로 두고, 쓰기는 `write(statements[])` 를 새로 판다
(`src/lib/db.ts`). 이 관문은 세 겹으로 잠겨 있다.

1. `ALLOW_DEV_WRITES` 가 아니면 **관문 안쪽에서** 던진다 — 라우트가 게이트를 잊어도 안 뚫린다
2. INSERT/UPDATE 만 통과 — DELETE·DDL 은 이 앱이 쓰지 않으므로 아예 거부 (주석으로 가려도 검사)
3. 넘긴 구문 전체가 **한 트랜잭션** — 상태 변경과 이력 로그가 따로 커밋되면 이력 없는 티켓이 생긴다

> `select()` 를 넓혀 쓰기를 허용하는 선택지는 처음부터 버렸다. 관문이 하나면 언젠가
> "조회인 줄 알았는데 쓰는" 코드가 생긴다.

### 2. 상태 전이는 표 하나가 정본이다

`src/lib/data/mutations.ts` 의 `TRANSITIONS` 가 (액션 → 다음 상태 + 찍을 컬럼 + 이력 문구)를
전부 쥔다. **표에 없는 액션은 실행되지 않는다**(fail-closed). 되돌리는 전이(진행→신청)는
일부러 넣지 않았다 — 상태를 되돌리면 이력이 꼬인다.

- 권한 판정은 여기서 하지 않는다. 라우트가 서버에서 티켓을 **다시 읽어** `canDo()` 로 판정한
  뒤에 부른다. 판정과 실행을 한 함수에 섞으면 둘 중 하나를 빠뜨린다.
- 처리내역 저장 권한은 액션 권한과 **별개 축**이다. 액션에 딸려 온 처리내역은
  `canDo("save")` 가 통과할 때만 반영한다.

### 3. 이력은 댓글 테이블의 로그행으로 남긴다

상태가 바뀌면 `NX_OPTREPORTR` 에 `IS_LOG_YN='Y'` · `PPROGRESS=새 상태` 행을 같은
트랜잭션에서 남긴다 — 시드가 만드는 로그행과 형식이 같아야 이력 탭이 섞이지 않는다.

- **`save` 는 로그를 남기지 않는다.** 저장할 때마다 쌓이면 이력 탭이 무의미해진다.
- **`suggestCancel`(취소 권유)은 로그가 아니라 사람 댓글**이다. 시스템 기록은 접혀 있어서,
  신청자에게 미읽음으로 보여야 하는 알림이 거기 들어가면 묻힌다.

### 4. 저장 시점에도 새니타이즈한다

읽기 경로만 거르면 **저장된 마크업이 DB 에 남는다**. 렌더 경로가 하나라도 새면 그때 터진다.
`sanitize()` 는 DOM 없는 순수 파서라 서버에서도 그대로 돈다(ADR-0005 의 교훈).

### 5. 접수번호는 그 고객사의 기존 번호를 이어받는다

`<접두>-<YYYYMM>-<일련 3자리>`. 접두는 원본에도 마스터 컬럼이 없어서 **그 고객사의 마지막
접수번호에서 물려받는다**. 첫 건이면 고객사 코드 앞 두 글자로 시작한다.

### 6. 재신청은 상태 전이가 아니라 새 신청이다

`reapply` 는 전이표에 없다. 화면이 `/requests/new?from=<접수번호>` 로 보내고, 서버가 원본을
**가시성 게이트를 통과해** 읽어 프리필한다. 저장 시 `REREQYN='Y'` · `P_ECHONUM` 으로 연결된다.

### 7. 202 는 성공이 아니다 — 화면은 `res.ok` 로 판정하지 않는다

쓰기가 꺼져 있으면 라우트가 **202 + `WRITE_DISABLED`** 를 준다. `Response.ok` 는 200–299 라
202 가 포함되므로, `if (res.ok)` 로 성공을 판정하면 저장되지 않았는데도 화면이 초안을 지우고
뱃지를 비운다 — 기본값이 '꺼짐'이라 **라이브 데모에서 항상** 그렇게 된다.

→ 성공 판정은 `res.status === 200`, 202 는 "여기까지 통과했다"는 **안내**로 표시한다.
   (신청 폼·보드·상세 시트·알림센터 네 곳이 같은 규약을 쓴다)

### 8. 내부 전용 댓글은 쓰기·읽기 축이 같아야 한다

`ADMIN_ONLY_YN='Y'` 는 **운영팀(INTERNAL)만** 만들 수 있고, 읽기 가드도 INTERNAL 에게만
열려 있다. 축이 어긋나면 "썼는데 본인에게도 안 보이는 댓글"이 생긴다.

판정은 `insertComment()` **안쪽**에 둔다 — 액션에 딸려 오는 댓글까지 같은 경로를 지나므로
호출자가 잊을 수 없다. (강등을 호출자에 두면 `addComment` 만 막히고 `applyAction` 꼬리가 뚫린다)

## 결과 (트레이드오프)

- **얻는 것**: 액션 하나를 추가할 때 고칠 곳이 표 한 줄 + `canDo()` 한 줄이다.
  같은 액션 라우트를 조회 화면·칸반 보드가 공유한다(ADR-0007) — 두 화면이 어긋날 수 없다.
- **포기하는 것**: 원본의 **낙관적 락**(모든 수정에 `updDt` 동봉)은 이식하지 않았다.
  우리 스키마에 갱신일시 컬럼이 없다. 대신 "서버가 티켓을 다시 읽어 재판정"이 그 자리를
  대신한다 — 남이 먼저 옮겼으면 상태가 달라져 `canDo()` 가 403 을 낸다. 마지막 쓰기가
  이기는 창은 남지만, 데모 규모에서 감수한다.
- **기본값은 꺼짐**: `ALLOW_DEV_WRITES` 없이 클론하면 화면은 판정까지만 하고
  202 로 "여기까지 통과했다"를 알려준다. 배포(Vercel)는 `:memory:` 라 켜도 인스턴스
  수명만큼만 유지된다(ADR-0004 의 주의사항 그대로).

## 검토한 대안

- **액션마다 전용 라우트** (`/api/tickets/[id]/approve` …) — 탈락: 권한 재판정·이력 기록·
  트랜잭션 처리가 라우트 수만큼 복제된다. 원본이 그렇게 흩어져 있었다.
- **ORM 도입(Drizzle/Prisma)** — 탈락: 원본 컬럼명을 그대로 쓰는 게 이 프로젝트의 제약이고
  (경계 한 곳에서만 변환), 스키마가 7테이블이라 얻는 것보다 잃는 게 많다.
- **낙관적 락 컬럼 추가(UPD_DT)** — 보류: 원본에 없는 컬럼을 시드 스키마에 만들면
  "원본 형태 유지" 규칙이 깨진다. 동시 편집이 실제 문제가 되면 그때 도입한다.

## 개정 (2026-08-18) — 기본값을 '허용'으로 뒤집는다

위 §"결과"의 "기본값은 꺼짐"을 폐기한다. **이제 기본이 허용이고, `ALLOW_DEV_WRITES=false`
일 때만 잠근다.**

- **왜 꺼 뒀었나**: 회사 개발 DB 를 직접 보던 시절(ADR-0002)의 안전장치다. 잘못 쓰면
  실데이터를 건드리니까.
- **왜 이제 켜나**: ADR-0004 로 자체 SQLite + 100% 가상 시드가 되면서 **지킬 대상이
  사라졌다.** 남은 건 "저장을 눌러도 아무 일도 일어나지 않는 데모"뿐이었고, 라이브
  데모에서는 그게 기본 경험이었다 — 신청·댓글·첨부 어디를 눌러도 202 안내만 떴다.
- **잠금장치는 그대로**: 플래그는 `write()` **관문 안쪽**에서 확인한다. `false` 로 두면
  라우트가 게이트를 잊어도 안 뚫린다. 202 계약(§7)도 그대로 살아 있다 — 잠긴 상태에서
  화면은 여전히 "여기까지 통과했다"를 보여주고, 성공 판정은 `200` 뿐이다.
- **서버리스의 성질은 감수한다**: 배포본은 `:memory:` 라 저장이 **인스턴스 수명까지만**
  산다. 콜드스타트가 나면 시드가 다시 깔린다(ADR-0004 에 이미 적힌 성질). 방문자가 한
  세션 안에서 만든 건은 그대로 보이고, 시간이 지나면 초기 상태로 돌아간다.
- **공개 데모라는 점**: 누구나 쓸 수 있게 됐지만 저장되는 곳은 그 인스턴스의 메모리이고,
  본문은 저장 시점에 새니타이즈된다(§4). 남는 위험은 "같은 인스턴스를 만난 다른 방문자가
  잠시 그 글을 본다" 정도다.
