# ADR-0009: 라이브 데모의 쓰기를 위해 공유 DB(libSQL)를 붙인다

- 날짜: 2026-08-18
- 상태: 채택 (ADR-0004 의 "환경변수 0개"를 **로컬 한정**으로 좁힌다)

## 맥락

쓰기 경로(ADR-0006)·첨부(ADR-0008)를 다 만들어 놓고도 **라이브 데모에서는 아무것도 저장되지
않았다.** 배포본의 DB 가 인스턴스 메모리(`:memory:`)라서다.

기본값을 '허용'으로 바꿔 실측해 보니 문제는 수명이 아니라 **일관성**이었다.
서버리스는 요청마다 다른 인스턴스가 응답할 수 있고 DB 는 그 인스턴스 안에 있다 —
방금 만든 건을 세 번 읽어 **2회가 404** 였다(`HB-202608-020`). 저장된 척하다 사라지는 쪽이
"저장 안 됨"을 알려주는 202 보다 나쁘다고 판단해 한 번 잠갔다(ADR-0006 개정).

하지만 잠근 데모는 이 프로젝트의 절반을 못 보여준다. 리뷰어가 신청·댓글·첨부·권한 판정을
**눌러볼 수 없다.** 그래서 저장소 쪽을 고치기로 했다.

## 결정

### 1. 공유 DB 는 libSQL(Turso)이다 — SQLite 호환이라 쿼리가 안 바뀐다

Postgres 로 갔다면 `INSERT OR REPLACE`, `date('now','-11 months')`, 그리고 **GROUP BY 의
bare column 이 MAX() 행을 따라가는 규칙**(알림센터가 여기 기대고 있다)이 전부 깨진다.
libSQL 은 SQLite 그 자체라 **데이터 계층 코드가 한 줄도 바뀌지 않았다.**

- 클라이언트는 `@libsql/client/web` — fetch 기반 순수 JS. 네이티브 바인딩을 끌고 오면
  서버리스 번들에서 터진다(ADR-0005 의 jsdom 사고와 같은 함정).
- `write()` 는 `batch(statements, "write")` 로 넘긴다 — **그게 곧 트랜잭션**이라
  "상태 변경과 이력 로그는 함께 커밋된다"는 ADR-0006 §1 이 그대로 유지된다.

### 2. 저장소가 쓰기 허용을 정한다 (플래그는 탈출구)

```
로컬 파일 DB            → 허용
서버리스 + 메모리        → 잠금  (인스턴스마다 달라 저장이 어긋난다)
서버리스 + 공유 DB      → 허용  (모든 인스턴스가 같은 데이터를 본다)
ALLOW_DEV_WRITES        → 주면 그 값이 이긴다
```

판정은 `write()` 관문 안쪽에 있다 — 라우트가 게이트를 잊어도 안 뚫린다.

### 3. 시드는 **로컬에서 만든 파일을 복사**한다

시드 생성기는 better-sqlite3(동기)에 묶여 있다. 원격에서 다시 돌리려면 생성기를 async 로
갈라야 하는데, 그건 시드의 결정성을 건드리는 일이다. 대신 `npm run db:seed:remote` 가
`.data/nexio.db` 를 통째로 복사한다(스키마도 `sqlite_master` 에서 읽어 온다 — 정의를 두 벌
관리하지 않는다). 로컬과 라이브가 **같은 데이터**임이 자명해진다.

### 4. 로컬은 여전히 환경변수 0개

`TURSO_DATABASE_URL` 이 없으면 예전 그대로다. 클론 → `npm run dev` → 끝.
ADR-0004 의 약속은 **로컬에 한해** 유지된다.

## 결과 (트레이드오프)

- **얻는 것**: 라이브에서 신청·댓글·첨부·상태 전이가 실제로 저장된다. 리뷰어가 권한 차이를
  눌러서 확인할 수 있다(역할 전환 → 같은 화면이 어떻게 달라지는지).
- **포기하는 것**:
  - **배포에 환경변수 2개가 생겼다.** "설정 없이 배포된다"는 자랑을 하나 잃었다.
  - **공개 데모가 공용 낙서장이 된다.** 누구나 쓴 글이 모두에게 보인다. 저장 시점
    새니타이즈(ADR-0006 §4)와 허용 목록 첨부(ADR-0008 §2)가 방어선이고, 더러워지면
    `npm run db:seed:remote` 로 되돌린다.
  - **무료 티어 한도**(행 읽기/저장 용량)에 걸리면 라이브가 멎는다. 그때는
    `ALLOW_DEV_WRITES=false` 한 줄로 읽기 전용 데모로 되돌아간다 — 잠금장치를 남겨 둔 이유다.

## 검토한 대안

- **Vercel Postgres/Neon** — 탈락: SQL 방언이 달라 데이터 계층을 다시 써야 한다(§1).
- **`/tmp` 파일 DB** — 탈락: 인스턴스별인 건 메모리와 똑같다. 문제가 수명이 아니라 일관성이었다.
- **읽기 전용 데모 유지** — 탈락: 만든 것의 절반(쓰기 경로·첨부·액션 권한)을 못 보여준다.
- **브라우저 안에서만 도는 데모(wasm SQLite)** — 탈락: 서버 권한 판정이 사라져
  이 프로젝트가 보여주려는 fail-closed 게이트가 통째로 무의미해진다.

## 켜는 법 (3단계)

1. [turso.tech](https://turso.tech) 무료 DB 생성 → URL·토큰 확보
2. 저장소 루트에 `.env.turso` 를 만들고 두 줄을 넣은 뒤 `npm run db:seed:remote`

   ```
   TURSO_DATABASE_URL=libsql://<db>-<org>.turso.io
   TURSO_AUTH_TOKEN=<토큰>
   ```

   ⚠️ `.env.local` 이 아니라 `.env.turso` 다 — `.env.local` 은 Next.js 가 자동으로 읽어서
   **로컬 개발까지 원격 DB 를 보게 된다.** 파일을 갈라 두면 로컬은 파일 DB 그대로다.
   (둘 다 `.gitignore` 의 `.env*` 에 걸려 커밋되지 않는다)

3. Vercel 프로젝트 환경변수에 같은 값 2개 추가 → 재배포

확인:

- `npm run db:verify:remote` — 앱이 기대는 SQLite 규칙을 원격이 지키는지 5가지로 검사한다.
  특히 **GROUP BY 의 bare column 이 MAX() 행을 따라가는 성질**(알림센터가 여기 기댄다)은
  표준 SQL 이 아니라 SQLite 의 동작이라, 조용히 다르면 엉뚱한 글이 대표로 뜬다.
  (2026-08-18 Turso 실측: 5개 항목 전부 동일)
- 라이브에서 `/api/diag` 의 `db.mode` 가 `shared(libSQL)`, `writes.allowed` 가 `true`.
