## 1. 화면 구조 — 마스터-디테일이 한 페이지에 눌려 있다

```
┌─ 검색 필터 (13조건)
├─ 목록 그리드
├─ [상단 액션 버튼] ← 선택된 행의 상태에 따라 표시  (고객측)
├─ 상세 폼          ← selectedRow 의 102필드
├─ 관리자 처리 폼    ← 접수/제안/처리결과/시간정산   (엔지니어측)
└─ 댓글
```

**핵심 문제**: 목록에서 행을 선택하면 **같은 페이지 아래쪽에 상세가 펼쳐진다**(`selectedRow` 전역 변수).
모달도, 라우팅도, 사이드패널도 없다. 그래서 스크롤이 끝없이 길어지고,
"지금 내가 어느 건을 보고 있는지"가 시각적으로 사라진다.

- input/select/textarea **69개** · modal **0개**
- 검색 조건은 13개뿐 → **나머지 56개는 상세 편집 컨트롤**이 목록 화면에 얹혀 있는 것

## 3. 버튼 — **두 개의 독립된 버튼 시스템**이 한 화면에 공존

| `btnCancelReq`                 | `p==='3'` && 신청자본인 && 고객                       |

## 6. UX 재설계 입력 (P2 로 넘길 것)

1. **목록과 상세를 분리한다** — 상세는 사이드 시트(Sheet) 또는 라우팅. 현재의 "아래로 펼치기"를 버린다.
2. **두 버튼 시스템을 하나의 액션 바로 통합** — 사용자는 "내가 지금 할 수 있는 것" 하나만 보면 된다. 상단/하단 구분은 구현 사정이지 사용자 사정이 아니다.
3. **상태를 시각화한다** — 12단계 워크플로를 Stepper 로. 지금은 코드값 텍스트뿐이라 "어디까지 왔는지" 안 보인다.
4. **고객사별로 안 쓰는 단계는 렌더하지 않는다** — `testYn`/`systemYn` 이 'N' 이면 관련 14필드와 버튼을 아예 만들지 않는다.
5. **댓글을 전면으로** — "고객과 소통"의 실체인데 102필드 아래에 묻혀 있다.
6. **필터 13개를 상단에 압축** — 나머지 56개 컨트롤은 상세로 이동.
