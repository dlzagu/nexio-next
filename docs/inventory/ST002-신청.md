## 1. 요약 — 3화면 중 가장 단순하다

| 항목        | 값                                                                      |
| ----------- | ----------------------------------------------------------------------- |
| 줄수        | 2,599 (조회의 **39%**)                                                  |
| 입력 컨트롤 | **20개** (고유 id 기준)                                                 |
| 버튼        | **4개** — `btnSave` `btnReset` `btnHelpToggle` `btnOpenReferrerSetting` |
| 모달        | 0                                                                       |
| 상태        | 없음 (신규 등록 전용, 워크플로 진입 전)                                 |

## 3. 저장 검증 체인 (L2098~2144) — 순차 8단계

```
1. 고객사를 선택해 주세요
2. 신청자를 선택해 주세요
3. 이메일 정보가 없습니다 — 신청자 이메일을 먼저 등록해 주세요
4. 분야를 선택해 주세요
5. 제목을 입력해 주세요
6. {첫 섹션명}을(를) 입력해 주세요     ← getFirstSectionTitle() 동적
7. 증상을 입력해 주세요
8. 요청내용을 입력해 주세요
→ Alert.confirm('서비스 신청을 등록하시겠습니까?') → POST /eco/request/save
```

> **재설계 시 개선점**: 지금은 저장을 눌러야 하나씩 튀어나오는 순차 alert 방식이다.
> 8번 걸리면 8번 눌러야 한다. → 필드별 인라인 검증 + 제출 시 전체 요약으로 바꾼다.

### 이미지 붙여넣기 가드 (특이 로직)

외부(메일/웹)에서 복사한 이미지는 저장되지 않아 **차단**한다 (L1411, L2409).
"캡처하거나 파일로 저장한 뒤 붙여넣어 달라"는 안내. → 재설계 시 유지해야 하는 실사용 제약.

## 4. 첨부 — 2단계 업로드

```
POST /Mobile/uploadFile    → 파일 업로드
POST /Mobile/saveFiledata  → 메타 저장
```

> ⚠️ 경로가 `/Mobile/*` 이다. 모바일용 엔드포인트를 재사용 중.
> 조회(ST001)는 `OK_UPLOAD_URL` 변수를 쓴다 → **두 화면의 업로드 경로가 다르다.** P1.s6 에서 확인.

## 5. 재신청 흐름

`reReqYn` / `pEchoNum` 으로 이전 건을 불러온다 (L1239 "재신청 정보 불러오기에 실패했습니다").
조회 화면의 `btnReapply`(종료상태 9·11·12에서 노출)가 이 화면으로 진입시키는 것으로 보인다.
→ **조회와 신청이 재신청으로 연결된다.** 라우팅 설계 시 반영.

---

## 6. UX 재설계 입력 (P2)

1. **검증을 인라인으로** — 순차 alert 8단계 → 필드별 실시간 + 제출 시 요약
2. **계약시간 3종은 입력이 아니라 정보** — `disabled` 인데 입력칸 모양이다. 정보 표시 컴포넌트로 분리
3. **참조자 UI가 3중** (`refGroupSelect` + `ccInput` + `refEmail`) — 하나의 토큰 입력 컴포넌트로 통합
4. **Step 분해는 불필요할 수 있다** — 20필드면 한 화면에 담긴다. 조회와 달리 **쪼개는 게 목적이 아니다**.
   기본/상세 2단 구성 정도면 충분
5. 재신청 진입 시 이전 값 프리필 상태를 시각적으로 구분
