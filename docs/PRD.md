# PRD — 넥시오 벤더포털 Next.js 전환 (MVP)

> 골격 문서. **확정된 것만 적혀 있고, 미확정은 `⬜ 미확정` 으로 표시했다.**
> 추측으로 채우지 마라 — 사용자와 확정한 뒤 표시를 지우고 내용을 넣는다.

## 1. 문제

기존 벤더포털의 서비스 조회 화면(`c4web/ST001.jsp`)이 **6,611줄 한 화면**이다.
목록·상세·편집·워크플로 액션이 한 페이지에 세로로 눌려 있고, 상태 12종 × 버튼 25종 ×
권한 축 11개가 JSP 전역에 흩어져 있다. 유지보수 비용과 사용자 인지 부하가 모두 높다.

실측(`inventory/data-profile.md`)이 밝힌 더 큰 문제 — **화면에 있는 워크플로의 일부가
도입 이래 한 번도 실행되지 않았다**(상태 7·8·10 = 전 기간 0건). 쓰지 않는 단계를 위해
필드 8개 · 버튼 3개 · 권한 축 4개 · 상태 분기 2블록이 상주 중이다.

## 2. 목표

- MVP 3화면을 Next.js 로 재구축하고, 정보 구조를 **단계/패널/모달로 분해**한다
- 디자인 방향: 애플·테슬라·토스 계열의 미니멀·직관·세련됨 (B2B 밀도는 유지)
- Spring 백엔드는 **수정하지 않는다**. Next.js 는 화면 + BFF 만 담당

## 3. 비목표 (Non-goals)

- Spring 백엔드 수정 — API 가 모자라면 별건으로 논의
- ST003(선급금 정산) · ST004(Cross charge) — `getData20` 게이트웨이 경유라 통로가 다름
- `admin/*` 화면 전체 (60개 이상)
- 다국어 — MVP 는 한국어 전용. i18n 라이브러리 도입 금지
- 원본 repo(SVN) 로의 커밋 — 사용자만 수행

## 6. 성공 기준

⬜ **미확정** — 사용자와 확정할 것. 정할 축은 다음 정도다.

- 화면당 초기 로드 시간 / 브라우저 요청 수 (대시보드는 19+ → 1 로 줄이는 것이 설계 목표)
- 신청 완료까지의 클릭·입력 수
- 조회 화면에서 "다음에 뭘 해야 하나"를 파악하는 데 걸리는 시간
- 기존 화면 대비 문의 감소 (특히 "조회가 안 돼요" — 비공개 78.6% 가 유력 원인)

## 7. 제약

- Spring 은 정렬 파라미터를 지원하지 않는다 → 뷰를 나눠 클라이언트/서버 정렬 병행
- 인증은 form-login + 세션 쿠키(`PORTALSESSIONID`). JWT 아님 (`decisions/ADR-0001`)
- 기존 데이터 2.3만 건이 HTML 로 저장돼 있다 → 새니타이즈 필수
- 회사 정책: 요청 취소의 실행 주체는 **신청자 본인만**
