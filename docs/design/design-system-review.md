### 우리 요구를 충족한 부분

- **밀도 프리셋 토글** — "폰트 크기와 간격 토큰은 바뀌지 않는다. 흔들리는 건 컨트롤 높이·행 높이·필드 간격뿐" → 원칙 P8(B2B 밀도) 충족
- **폼 그리드 12컬럼** — "조회 필터는 4컬럼(3span), 신청 폼은 2컬럼(6span)" → 우리 화면 설계에 바로 대응
- **a11y: 상태별 3중 인코딩** — 색 외 신호 명시 → 원칙 P5·차트 요구 충족
- **포커스 링** 2px + 2px 오프셋, `:focus-visible` → 마우스 클릭 시 링 미표시
- **Sheet 해부도** — sticky header/footer, body 단독 스크롤 `overscroll-behavior:contain`, 변경 시 확인 모달
- **다크/라이트** — `[data-theme="dark|light"]` 양방향

## 3. 🔴 누락 4건 — P5 에서 우리가 만든다

디자인 시스템이 **파운데이션 범위**(1층 토큰 + 2층 프리미티브)로 발주됐으므로 정상적인 누락이다.
다만 **MVP 3화면에 실제로 필요**하므로 P5 에서 채운다.

| #   | 누락                         | 왜 필요한가                                                                                                    | 대응                                                                                                       |
| --- | ---------------------------- | -------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | **Combobox** (검색형 select) | 모듈 **26개** 선택 (`data-profile.md` §5). 일반 select 로는 못 씀                                              | `cmdk`(shadcn Command) + `input`·`sheet` 토큰 재사용                                                       |
| 2   | **Chip / Token input**       | 참조자 3중 UI 통합 (`redesign-ST002` §4)                                                                       | 토큰은 이미 있음 (`--bg-selected` "필터 칩", `--sp-8` "칩 간격", `--r-xs` "미세 칩") → **컴포넌트만 조립** |
| 3   | **Empty state**              | 🔴 원칙 P7 의 핵심. 비공개 **78.6%** 라 빈 목록이 정상 동작인데 설명이 없으면 "조회가 안 돼요" 문의가 계속된다 | `card` + `fg-muted` 로 조립. 문구는 `redesign-ST001` §1 에 이미 작성됨                                     |
| 4   | **RichText(prose) 스타일**   | 처리결과 7종 + 댓글이 **HTML 렌더**(2.3만 건). Tiptap 편집기 + 읽기 뷰 양쪽                                    | `type` 토큰 기반 `.prose` 스타일 정의                                                                      |

> 1·2·3 은 **기존 토큰 조합으로 조립 가능**하다 — 새 토큰을 요청할 필요 없다.
> 4 는 타이포 토큰을 HTML 태그에 매핑하는 작업이라 마찬가지.

## 4. ⚠️ 조정 필요 1건 — 탭 개수

|                          | 탭 구성                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 디자인 시스템 `compose`  | **4탭** × 3~5 아코디언 = 탭당 최대 30필드 (예시: 기본 28 / SLA 24 / 이력 30 / 첨부 18) |
| 우리 `redesign-ST001` §2 | **5탭** — 요청내용 / 처리결과 / **댓글** / 첨부 / 이력                                 |

디자인 쪽 4탭에는 **댓글이 없다.** 우리는 "댓글 = 고객 소통의 실체이므로 전면으로"라고 결론냈다
(`redesign-ST001` §2). 선택지:

| 안           | 내용                                                                           |
| ------------ | ------------------------------------------------------------------------------ |
| **A (권장)** | 5탭 유지. 탭당 필드 수는 여전히 30 이하라 `compose` 규칙(1080px)을 깨지 않는다 |
| B            | 4탭 + 댓글을 Sheet 하단 고정 영역으로 (탭 전환 없이 항상 보임)                 |

> B 가 소통 관점에선 더 낫지만 Sheet 높이를 잡아먹는다. **A 로 가되 P6 구현 시 실제 데이터로 재평가.**

## 부록 — 아티팩트 재추출 방법

아티팩트는 gzip+base64 번들이라 그냥 저장하면 껍데기만 남는다.

1. `WebFetch` 로 아티팩트 URL 을 가져오면 원본 HTML 이 파일로 저장된다
2. `<script type="__bundler/template">` 의 JSON 을 파싱 → 실제 HTML
3. `<style id="nexio-tokens">` 블록이 토큰 CSS
