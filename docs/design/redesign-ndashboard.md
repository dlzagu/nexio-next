# 대시보드 재설계 (ndashboard)

> 원본 3,104줄 · 위젯 14 · GET 14 · 쓰기 없음 · Chart.js 캔버스 3
> 근거: `../inventory/ndashboard-대시보드.md` · 기준: `ux-principles.md`
> **구현 1순위** — 읽기 전용이라 디자인 시스템을 안전하게 검증할 무대.

## 0. 이 화면의 주된 결정 한 문장 (P1)

> **"오늘 내가 손대야 할 건이 무엇인가."**

지금은 위젯 14개가 평면 나열이라 "무엇을 보라는 화면인지"가 없다.
대시보드는 감상용 지표판이 아니라 **조회 화면으로 들어가는 관문**이어야 한다.

→ 모든 위젯은 **클릭하면 해당 조건이 걸린 조회 화면으로 이동**한다. 막다른 위젯을 만들지 않는다.

---

## 1. 역할별로 첫 화면이 다르다 (P1)

서버가 이미 데이터를 격리하므로(`effectiveCustCode`) **화면 구성만** 바꾸면 된다.

| 사용자                      | 기본 관심사       | 상단에 놓을 것                      |
| --------------------------- | ----------------- | ----------------------------------- |
| **내부(운영팀)** `B0001_01` | 팀 전체 처리 현황 | 조직 지표 + 내 미처리               |
| **고객사** `B0001_02`       | 내가 낸 요청 상태 | **내 요청 현황** + 우리 회사 미해결 |
| **외부업체** `B0001_03`     | 배정받은 건       | 내 미처리                           |

> ⚠️ 용어: `EXTERNAL`(B0001_02)이 실제로는 **고객사 직원**이다. TS 이식 시
> `INTERNAL / CUSTOMER / VENDOR` 로 개명 (`ndashboard-대시보드.md` §5).

### 구역 ↔ API 매핑

| 구역             | 위젯                                                 | API                                                                                        |
| ---------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **① 지금 할 일** | 요약카드 4 · 내 미처리 · 회사 미해결                 | `my-status-counts` `my-pending` `company-unresolved` `stats`                               |
| **② 현황**       | 추이 · 상태분포 · 소요시간 · 상위고객사 · 담당자실적 | `trend` `status-distribution` `processing-duration` `top-customers` `assignee-performance` |
| **③ 소식**       | 공지 · 최근요청 · 영상                               | `notices` `recent-requests` `youtube-videos`                                               |

> 고객사 사용자에게 ②의 `assignee-performance`(담당자별 실적)는 의미가 없다 → 역할별 숨김.

## 3. 중복 호출 정리 (P1 인벤토리 발견)

원본은 같은 API 를 화면 여러 곳에서 반복 호출한다.

| API               | 원본 호출 횟수 | 재설계           |
| ----------------- | -------------: | ---------------- |
| `recent-requests` |          **3** | 1회 fetch → 공유 |
| `my-activity`     |              2 | 1회              |
| `notices`         |              2 | 1회              |
| `youtube-videos`  |              2 | 1회              |

→ **14 API 를 페이지당 14회 호출**로 정리 (현재 19회+). 서버 부하와 초기 로딩 모두 개선.

> `my-activity` 는 재설계 레이아웃에서 자리를 못 찾았다. **MVP 제외 후보** — 사용자 확인 필요.

## 4. 차트 (P8 · dataviz 규격)

Chart.js 3종을 유지하되 **디자인 시스템 팔레트를 공유**한다.

| 차트                  | 형태 | 주의                                                                              |
| --------------------- | ---- | --------------------------------------------------------------------------------- |
| `trend`               | 라인 | 기간 축 — 이상치(`1900-01-01`) 제외                                               |
| `status-distribution` | 도넛 | **완료가 94.9%** → 그대로 그리면 원 하나가 됨. **미완료만** 또는 완료를 분리 표기 |
| `processing-duration` | 바   |                                                                                   |

> 🔴 `status-distribution` 은 데이터 분포상 지금 형태로는 정보량이 0에 가깝다.
> "완료 4,979 / 진행 95 / 해결안 57 / …" 를 한 도넛에 그리면 나머지가 안 보인다.
> → **완료 제외 후 미완료 270건만** 그리거나, 완료를 별도 큰 숫자로 빼고 나머지를 도넛으로.

- 상태를 **색만으로 구분하지 않는다** (접근성) — 라벨/패턴 병행
- 색 순서는 워크플로 순서(대기→신청→진행→해결안→완료)를 따른다
